# دليل تعديل MangaFlow

هذا الدليل موجّه لمن يريد تغيير الموقع بنفسه من GitHub أو من محرر مثل VS Code. بنية المصدر مقسّمة بحسب المسؤولية؛ لذلك لا تحتاج إلى البحث في ملف واحد ضخم أو إعادة إنشاء المشروع.

## خريطة الملفات

| المسار | ماذا يعدّل؟ |
| --- | --- |
| `client/src/App.tsx` | مسارات الصفحات وربط كل مسار بصفحته. |
| `client/src/components/AppShell.tsx` | إطار الموقع والتنقل العلوي والسفلي المشترك. |
| `client/src/pages/Home.tsx` | الصفحة الرئيسية، البحث، مرشّحات المانغا اليابانية والمانهوا الكورية، وعرض الكتالوج. |
| `client/src/pages/MangaDetails.tsx` | تفاصيل العمل وقائمة الفصول وخيارات لغات الفصول. |
| `client/src/pages/Reader.tsx` | قارئ الصفحات، اتجاه القراءة، والانتقال بين الفصول. |
| `client/src/pages/Library.tsx` | المفضلة وسجل القراءة المحفوظان محليًا في المتصفح. |
| `client/src/components/MangaCard.tsx` | شكل بطاقة العمل التي تظهر في قوائم الكتالوج والمكتبة. |
| `client/src/lib/mangadex.ts` | أنواع بيانات MangaDex وطلبات الكتالوج وعناوين الصور وأسماء اللغات والتصنيفات. |
| `client/src/lib/library.ts` | قراءة وكتابة المفضلة وتقدم القراءة في التخزين المحلي. |
| `client/src/index.css` | الألوان والخطوط والتخطيط والاستجابة للشاشات المختلفة. |
| `client/index.html` | عنوان الصفحة وبياناتها الوصفية وخصائص العربية ووسم Google verification. |
| `client/public/` | الصور والملفات الثابتة التي يجب أن تظهر من جذر الموقع، ومنها ملف Google verification. |
| `client/public/manus-routes.json` | قائمة صفحات الموقع؛ حدّثها عند إضافة أو إزالة مسار في `App.tsx`. |
| `server/mangadex.ts` | وسيط MangaDex لطلبات API والصور وحدود الاستخدام. لا تتجاوز قائمة المسارات المسموحة أو ضوابط الصور عند تعديله. |
| `server/_core/` | تكاملات التشغيل الخاصة بالمنصة والخادم. لا تغيّرها لتعديل شكل صفحات MangaFlow. |
| `client/src/components/ui/` | عناصر واجهة أساسية مشتركة؛ عدّل مكونات MangaFlow أولًا بدل تغيير عنصر عام قد يؤثر في عدة صفحات. |

## تعديلات شائعة

**تغيير النصوص:** عدّل النص في الصفحة المناسبة داخل `client/src/pages/`. أما النص المتكرر، مثل التنقل، فمكانه `AppShell.tsx`.

**تغيير الألوان أو الهوامش:** استخدم `client/src/index.css`. ابدأ بمتغيرات الألوان في أعلى الملف، ثم عدّل قواعد المكوّن المقصود. راجع عرض الهاتف بعد أي تغيير في العرض أو الشبكات.

**تغيير نوع العمل المعروض:** مرشّح الكتالوج في `Home.tsx` يستخدم لغة الأصل اليابانية `ja` للمانغا والكورية `ko` للمانهوا. عند تعديل هذا السلوك، أبقِ معامل `originalLanguage[]` متوافقًا مع MangaDex.

**تغيير أسماء التصنيفات أو اللغات:** راجع خرائط التسميات في `client/src/lib/mangadex.ts`. قد يعيد MangaDex عنوانًا أو وصفًا بلغة غير العربية؛ يعرض التطبيق لغة المصدر بوضوح ولا يترجم النص تلقائيًا.

**إضافة صفحة:** أنشئ ملف الصفحة في `client/src/pages/`، أضف المسار في `client/src/App.tsx`، ثم أضفه إلى `client/public/manus-routes.json`. إذا احتاجت الصفحة رابطًا في التنقل، عدّل `AppShell.tsx` أيضًا.

**إضافة صورة ثابتة:** ضعها في `client/public/` واستدعها بمسار يبدأ بـ `/`. لا تحفظ صور الفصول يدويًا؛ تمر صور MangaDex عبر وسيط الخادم.

**تحديث إثبات ملكية Google:** وسم meta موجود في `<head>` داخل `client/index.html`، وملف HTML الثابت موجود في `client/public/`. لا تحذف أيًا منهما ما دمت تستخدم طريقة التحقق المقابلة في Search Console.

## سير عمل آمن

1. عدّل الملفات ذات الصلة فقط، واحتفظ بعملك في فرع أو commit واضح.
2. شغّل `pnpm check` ثم `pnpm build` قبل الحفظ.
3. لا ترفع أسرارًا أو مفاتيح API أو ملفات `.env` إلى GitHub. واجهة MangaDex العامة لا تحتاج إلى مفتاح خاص في المتصفح.
4. لا تغيّر وسيط MangaDex أو إعدادات الصور لتجاوز حدود المصدر أو حقوق أصحاب المحتوى.
5. ادفع التعديلات إلى الفرع `main` في GitHub، ثم انشر أحدث checkpoint من لوحة Webdev بزر **Publish**. راجع الموقع بعد النشر؛ نجاح البناء أو push وحده لا يثبت أن النسخة الجديدة أصبحت مباشرة.

للتشغيل محليًا والأوامر الأساسية، ابدأ بملف `README.md` في جذر المشروع.
